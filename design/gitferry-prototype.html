01 首次启动 · 选择扫描目录
GitFerry
让 GitHub 与 Gitee 之间的同步自动发生

GitFerry 会扫描下方目录中的 git 仓库，识别 remote 归属（GitHub / Gitee）， 按你为每个仓库设置的开关与方向，在后台定时自动同步。同步复用系统 git 与钥匙串凭据，不需要配置 webhook 或令牌。

扫描目录
~/Projects
~/dev
~/Documents

默认深度 4 层，自动跳过 node_modules、隐藏目录与 .git 内部。

仓库状态机

idle ──启用了同步──▶ checking ──fetch 两端比较──▶ synced （无差异，更新 last_synced）
                        │ 有差异（领先侧可 fast-forward）
                        ▼
                    syncing ──push 成功──▶ synced
                        │ push [rejected]（分叉）
                        ▼
                    conflict ──用户三选一（以某侧为准 / 稍后）──▶ syncing
                        │ 凭证失败 / 网络 / 仓库缺失
                        ▼
                     error ──指数退避（3 次后 3× 间隔）──▶ checking

全局任意时刻：idle / syncing(N/M) / conflict(≥1) / error(≥1)
路径失效：任意状态 ──仓库目录不存在──▶ missing （暂停轮询，保留配置，重新扫描可恢复）

账号状态（每平台）：unconfigured ──保存令牌+API 验证──▶ connected ──401──▶ invalid
connected / invalid 都会反映到依赖它的仓库错误文案与自动建仓可用性。

同步流水线（每仓库）

1. git fetch <两端> --prune                        # 只更新 remote-tracking，不动工作区
2. 逐分支比较 src-sha / dst-sha                     # refs/heads/*
   ├─ dst 缺分支 / dst 是 src 祖先  → push 领先侧（无 --force）
   ├─ src 是 dst 祖先              → 跳过
   └─ 分叉                          → conflict，暂停该分支
3. 逐 tag 比较                                      # refs/tags/*：缺则补推；已存在不覆盖
4. 结果写入状态与 last_synced，日志一条记录
红线：自动路径绝不 --force、绝不删 ref；镜像模式与强制对齐必须用户显式确认。

文案规范（所有错误给可操作提示）

凭据失败：「gitee push 被拒：钥匙串中没有该仓库的凭据。请在终端对该仓库执行一次 git push 以保存凭据，然后重试。」
目标仓库不存在：「gitee.com 上还没有同名仓库。请先在 Gitee 创建空仓库（不要初始化 README），或在设置中更换方向。」
单文件超限：「推送失败：仓库中存在超过 100MB 的文件，Gitee 不支持。可启用 Git-LFS 或排除该文件。」
分叉：「两端各有新提交，GitFerry 不会自动覆盖任何一侧。请选择权威一侧或手动合并。」
